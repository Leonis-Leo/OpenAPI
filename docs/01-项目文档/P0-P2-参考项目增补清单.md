# 参考 APIPark 后的 P0/P1/P2 增补清单

参考项目：`E:\MyProject\OepnAPI-study\APIPark`

本清单用于补充《P0-安全与质量改造清单》。参考重点是能力模型和产品闭环，不直接复制 Go/APINTO 的实现。

## 对比结论

当前项目已经具备：应用、AccessKey/SecretKey、接口信息、订阅审批、签名调用、网关、限流、调用日志和基础用户管理。

参考项目值得吸收的差距主要集中在：

1. API 服务目录与完整生命周期管理不足。
2. 上游服务治理和网关策略能力不足。
3. 团队/租户级权限模型不足。
4. 调用日志已有，但指标、告警、成本和导出能力不足。
5. 缺少 OpenAPI 导入校验、版本发布、变更 diff 和回滚。

## P0：建议尽快纳入

- [ ] **接口发布版本与回滚**：接口增加草稿、已发布、下线状态；发布生成版本快照，支持查看变更 diff 和一键回滚。
- [ ] **上游服务配置**：为接口增加 upstream、超时、重试、连接池和健康检查配置，避免路由逻辑与具体后端地址耦合。
- [ ] **网关故障保护**：补充熔断、失败重试上限、超时、降级响应和上游健康状态，防止单个上游拖垮网关。
- [ ] **敏感数据脱敏策略**：对请求参数、响应体和调用日志按字段配置脱敏，覆盖密码、Token、身份证、手机号等常见敏感字段。
- [ ] **审计日志查询与导出**：当前已有写入能力，继续增加管理员筛选、操作前后值对比、失败记录查询和 CSV 导出。
- [ ] **生产配置启动自检**：启动时检查 JWT 密钥、数据库密码、Redis、RabbitMQ 和 Cookie Secure 配置，发现默认凭据时给出明确告警或拒绝生产启动。

## P1：平台能力增强

- [ ] **服务市场/服务目录**：服务按目录、标签、负责人、状态分类；支持开发者搜索、查看文档、申请订阅。
- [ ] **OpenAPI 导入与校验**：支持导入 JSON/YAML，校验路径、方法、参数、响应结构，并自动生成接口信息和 Swagger 文档。
- [ ] **接口文档版本化**：保存请求参数、响应示例、Header、错误码和变更历史，支持在线预览和导出。
- [ ] **策略中心**：将限流扩展为按应用、用户、IP、接口、方法、路径的策略，并支持缓存、IP 黑白名单、CORS 和请求/响应改写。
- [ ] **灰度发布**：支持按应用、用户、Header、IP 或比例路由到不同版本，保留灰度流量和回滚记录。
- [ ] **团队与细粒度 RBAC**：从单一 admin/user 扩展到组织、团队、成员、角色和资源权限，隔离应用、接口、订阅和日志。
- [ ] **证书管理**：统一管理 HTTPS/TLS 证书、过期时间和续期提醒；网关按域名绑定证书。
- [ ] **可观测性看板**：增加 QPS、成功率、P50/P95/P99、4xx/5xx、上游耗时、限流/熔断次数和可用性趋势。
- [ ] **日志与数据导出**：调用日志支持按时间、应用、接口、状态筛选，支持 CSV/JSON 导出及脱敏下载。
- [ ] **异步事件与可靠投递**：调用统计、审计、告警等事件增加重试、死信、幂等和积压监控。

## P2：差异化与规模化能力

- [ ] **多租户隔离**：租户级数据隔离、配额、账单和独立密钥空间。
- [ ] **多认证方式**：在 AK/SK 基础上增加 API Key、Basic、JWT、OAuth2，并按应用选择认证方式。
- [ ] **AI Provider/模型管理**：统一管理模型供应商、模型 Key、余额、模型路由和 Token 用量；仅在项目确定 AI 网关定位后实施。
- [ ] **Prompt API 与统一格式**：将模型和 Prompt 模板封装成标准 REST API，统一错误格式、超时、重试和 Token 统计。
- [ ] **MCP 服务暴露**：将已发布接口按全局、应用、服务维度暴露为 MCP 工具，补充工具权限和调用审计。
- [ ] **协议转换插件**：按需支持 gRPC/HTTP、Dubbo/HTTP 等协议转换，以及 Mock、请求改写和响应格式化插件。
- [ ] **集群与控制面/数据面分离**：管理端负责配置下发，网关节点负责流量转发，支持多实例、配置版本和节点健康检查。
- [ ] **国际化与开放平台门户**：增加中英文、繁体、日文等语言包，以及面向开发者的开放 API 门户。

## 推荐实施顺序

`版本发布/回滚` → `上游与超时重试` → `熔断与脱敏` → `审计查询导出` → `服务目录/OpenAPI 导入` → `策略中心/灰度` → `团队 RBAC/多租户` → `AI/MCP/协议插件`。

## 暂不建议直接照搬的内容

- APINTO、EOSC、NSQ、InfluxDB、Loki 等基础设施：当前项目已有 Spring Boot、RabbitMQ、Redis 和 MySQL，先补能力抽象，避免无明确指标的中间件迁移。
- 35+ AI Provider：只有在确定平台转向 AI 网关后再建设，当前优先完善通用 API 生命周期。
- 全量插件市场：先抽象策略接口并落地 3~5 个高价值策略，再考虑插件动态加载。
