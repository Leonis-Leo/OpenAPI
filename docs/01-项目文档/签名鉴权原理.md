# 签名鉴权原理

## 核心思想

每个应用分配一对 `AccessKey / SecretKey`：

- AccessKey：标识身份，随请求传输
- SecretKey：仅调用方与服务端持有，不随请求传输，用于计算签名

## 签名计算

签名内容格式（`SignatureUtils.buildSignContent`）：

```text
METHOD\n请求路径\n排序后的参数
```

- 参数包含业务参数 + `timestamp` + `nonce`，按 key 字典序拼接为 `k=v&k=v`
- 使用 `HMAC-SHA256 + SecretKey` 计算，输出小写十六进制

示例：

```text
GET
/api/demo/name
nonce=xxx&prefix=Hi-&timestamp=1785593534471
```

## 服务端校验步骤

1. 校验签名请求头（AccessKey / timestamp / nonce / signature）完整
2. 时间戳防过期：`|当前时间 - timestamp| <= 5 分钟`
3. 查询 AccessKey 对应的 SecretKey
4. nonce 防重放：写入 Redis（key：`openapi:nonce:{ak}:{nonce}`，5 分钟过期），重复即拒绝
5. 重建签名内容并比对（常量时间比对，防时序攻击）

## 为什么能防重放

攻击者截获请求后重放，时间戳可能过期；即使立即重放，nonce 已在 Redis 中记录，第二次请求被拒。
