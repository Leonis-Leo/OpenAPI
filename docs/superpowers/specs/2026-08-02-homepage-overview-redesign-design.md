# 首页概览重设计（Dashboard）设计文档

日期：2026-08-02
状态：已评审（用户确认，含 2 处修订：排行 TOP 10、趋势图增加失败量）

## 1. 背景与目标

当前 `/dashboard` 首页仅由 6 张统计卡 + "快速开始" + "快捷入口"组成，信息层级一般、没有利用后端已有的统计能力。目标是把首页重做为一个**角色感知的完整数据大盘**：

- 管理员：一屏内看到平台关键指标、调用趋势、TOP 10 接口/应用排行和最近调用动态；
- 普通用户：看到个人资源概览 + 开发指引，不请求任何仅管理员可用的统计接口。

纯前端改造，零后端改动，不加新依赖，并适配现有暗色模式。

## 2. 范围

### 2.1 范围内

- 重写 `openapi-web/src/views/DashboardView.vue` 主内容区；
- 新增首页专用子组件（见 §4.3）；
- 首页数据的加载/骨架屏/错误/空态处理；
- 响应式（320 / 768 / 1024 / 1440）与暗色模式适配；
- 键盘可访问性与对比度达标。

### 2.2 范围外

- 不改 `AdminLayout.vue`（侧边栏/顶栏/主题开关）与路由；
- 不改后端任何接口、权限、数据结构；
- 不改 `StatsView.vue` 等既有页面（本设计与其风格保持一致）；
- 不加新依赖（继续用 Element Plus 2.9 + ECharts 6 按需引入）。

## 3. 角色与数据权限

后端 `/v1/stats/**` 全部要求 `admin` 角色（`StatsController.requireAdmin`），普通用户调用返回 403。因此：

| 数据模块 | 管理员 | 普通用户 |
|----------|--------|----------|
| 我的应用 / 已订阅接口 / 可调用接口 | 有 | 有 |
| 累计调用 / 成功率 / 待审批订阅 | 有（前两者来自 statsOverview） | 无 |
| 调用趋势、TOP 排行、最近动态 | 有 | 无（不发起请求） |
| 快速开始 / 快捷入口 | 有 | 有 |

## 4. 页面结构与组件设计

### 4.1 管理员视图（自上而下）

1. **页头**：左侧"概览"标题 + 问候语（含当天日期，如"2026-08-02 星期日"）；右侧"刷新"按钮（图标 + 文字，非纯图标）。
2. **统计卡行**（6 张，`xs:12 sm:12 md:8 lg:4 xl:4`，lg 起一行 6 张）：我的应用 / 已订阅接口 / 可调用接口 / 累计调用 / 成功率（成功绿）/ 待审批订阅（警示橙）。每张卡：左图标、右数值，点击跳转对应页面，加载时骨架屏。
3. **中段双栏**（`lg 14 / 10`，lg 以下堆叠）：
   - 左：**调用趋势**——ECharts 平滑面积图，7 / 30 / 90 天切换，三条序列：调用量、成功量、失败量；图例 + 悬浮提示；暗色模式换色板。
   - 右：**调用排行**——tab 切换"接口 / 应用"，**TOP 10** 紧凑列表：名次、名称（超长省略）、调用量、成功率标签；行可点击跳转 `/stats`。
4. **底段双栏**（`lg 14 / 10`）：
   - 左：**最近调用动态**——最近 8 条日志：接口、应用、状态码、成功/失败图标 + 耗时 + 时间；点击跳转 `/logs`。
   - 右：**快速开始 + 快捷入口**——三步指引（应用管理 → 接口管理 → SDK 签名调用）+ 应用管理 / 接口管理 / 调用统计 / API 日志四个链接。

### 4.2 普通用户视图

- 统计卡行只显示 3 张：我的应用 / 已订阅接口 / 可调用接口；
- 下方保留"快速开始 + 快捷入口"；
- 不渲染也不请求趋势、排行、最近动态、statsOverview、待审批（避免 403 噪音与无意义请求）。

### 4.3 组件拆分（每个文件 < 200 行）

```
src/views/DashboardView.vue        # 容器：角色分支、数据编排、刷新、错误汇总
src/components/dashboard/
  StatCard.vue                     # 统计卡（图标/数值/语义色/点击/骨架）
  TrendChart.vue                   # 调用趋势图（7/30/90、三序列、暗色适配）
  RankList.vue                     # 接口/应用 TOP 10 排行（tab + 成功率标签）
  RecentLogs.vue                   # 最近调用动态列表
  QuickStart.vue                   # 快速开始 + 快捷入口
```

容器负责数据获取，展示组件只接收 props 并 emit 事件，保持单一职责（frontend-ui-engineering 的 container/presentation 模式）。

## 5. 数据流与接口

全部复用 `src/api/index.ts` 现有函数，仅当类型缺失时补充类型定义：

| 模块 | 接口 | 参数 | 说明 |
|------|------|------|------|
| 我的应用 | `listApps(userId)` | 当前用户 id | 取 length |
| 已订阅接口 | `mySubscribes()` | - | filter `status === 1` 取 length |
| 可调用接口 | `listInterfaces()` | - | 取 length |
| 累计调用 / 成功率 | `statsOverview()` | - | 仅 admin |
| 待审批订阅 | `listSubscribes(0)` | status=0 | 仅 admin |
| 调用趋势 | `statsDaily(days)` | 7/30/90 | 仅 admin；`fail = total - ok`（接口无独立 fail 字段） |
| 调用排行 | `statsTopInterfaces(10)` / `statsTopApps(10)` | limit=10 | 仅 admin |
| 最近动态 | `listApiLogs({ current: 1, size: 8 })` | - | 仅 admin |

加载策略：`onMounted` + `onActivated`（keep-alive 下返回页面自动刷新）；"刷新"按钮手动触发；各模块并行请求（`Promise.all`），模块间互不阻塞。

## 6. 状态处理

- **加载**：统计卡骨架屏；图表与排行区 `v-loading` 或骨架；不出现大面积空白。
- **错误**：模块级错误提示 + 重试按钮；单个模块失败不影响其他模块渲染。
- **空态**：趋势无数据 → "暂无调用数据，调用接口后即可查看趋势"；排行无数据 → "暂无可调用记录"；最近动态无数据 → "暂无调用日志"。
- **刷新中**：保留旧数据渲染，不闪烁（stale-while-revalidate 式体验）。

## 7. 视觉与交互规范

- **间距**：遵循 4px 基数（8/12/16/24），不使用 13px、2.3rem 之类自定义值。
- **颜色**：只用语义 token——`--el-color-primary/success/warning/danger`、`--el-text-color-primary/secondary/regular`、`--el-border-color`、`--el-bg-color-page`；不写裸十六进制；正文灰字不用 `#909399`（改用 secondary token 保证对比度）。
- **卡片**：Element Plus 默认圆角（`--el-border-radius-base`）与边框；仅可点击卡片在 hover 时加轻阴影（`--el-box-shadow-light`）。
- **统计卡图标**：置于浅色语义底色块中（用 `color-mix` 与 token 混合，不用渐变、不用紫色）。
- **禁止项**：无渐变、无紫/靛主色、无超大圆角、无纯装饰 hero、不用 Lorem 文案。
- **交互**：所有可点元素为原生 `<button>` / 路由跳转，键盘可聚焦且有可见 focus 态；行 hover 反馈；跳转统一 `router.push`。

## 8. 响应式与暗色模式

- 断点：320 / 768 / 1024 / 1440 均需验证；统计卡 2 → 3 → 6 列递进；双栏在 `lg` 以下堆叠；表格横向滚动（base.css 已有）。
- 暗色：`document.documentElement.classList` 已有 `dark` 接入（main.ts 引入 `element-plus/theme-chalk/dark/css-vars.css`）；新组件全部用 CSS 变量自动适配；ECharts 在初始化与主题切换时读取 token（`getComputedStyle`）生成色板，并监听窗口 resize 重绘。

## 9. 无障碍（WCAG 2.1 AA）

- 统计卡、排行行、动态行均为可聚焦元素（按钮/链接），Enter/Space 可激活；
- 图标不单独传达状态：成功/失败配文字或标签（如成功率百分比、状态码）；
- 文字对比度 ≥ 4.5:1（正文），大号数字 ≥ 3:1；
- 图表为辅助信息，容器提供 `aria-label` 说明（如"近 7 天调用趋势图"）；
- "刷新"按钮有可见文字，不做纯图标按钮。

## 10. 测试与验证

1. `npm run build`（`vue-tsc --noEmit` + `vite build`）零错误；
2. 用 browser-use（CDP 控制本机 Chrome）在 1440 / 1024 / 768 / 320 四档验证：管理员与普通用户两种账号、亮/暗两种主题；
3. 检查：无控制台错误、Tab 键全流程可达、加载骨架与空态可见、排行榜 TOP 10 完整渲染、趋势图三条序列（失败量 = 调用量 - 成功量）正确；
4. 回归：登录、其他菜单页不受影响。

## 11. 非目标与后续

- 不新增"我的调用趋势"等个人维度统计（后端无接口，属后续工作）；
- 不引入 React Query / Zustand 等状态库（当前复杂度不需要）；
- 首页不做实时轮询（保持手动刷新 + 页面激活刷新）。

## 12. 决策记录

| 决策 | 理由 |
|------|------|
| 采用方案 A（经典数据大盘） | 关键指标一屏可见，全部复用现有接口，风险最低 |
| 排行 TOP 10 | 用户确认（原 TOP 5 上调） |
| 趋势图三条序列：调用量/成功量/失败量 | 用户确认；失败量由 `total - ok` 计算 |
| 角色感知渲染，普通用户不请求 stats | 后端 stats 接口仅 admin，避免 403 |
| 组件拆分到 `src/components/dashboard/` | 单文件 < 200 行，容器/展示分离 |
| 语义 token 替代裸色值 | 暗色模式自动适配 + 对比度达标 |
